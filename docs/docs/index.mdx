Towbar is an open-source, self-hosted deployment platform for Ubuntu servers. Keep workload definitions in Git; Towbar syncs them into inventory and runs deployments over SSH.

Services can build from a Dockerfile, static files, Railpack, Nixpacks, or Buildpacks; run a prebuilt image; or use Docker Compose. Datastores provide managed database and cache engines. The dashboard brings together releases, previews, secrets, backups, monitoring, and logs.

## How it works

1. [Install the control plane](/docs/self-hosting/installation) and create your team.
2. Register a [server](/docs/servers/register) with verified SSH access.
3. Connect a [repository](/docs/repositories/connect), map an environment to a branch, and sync its manifests.
4. Supply declared [secret values](/docs/secrets), deploy, and check the running workload and its public route.

A sync accepts configuration; a deployment executes it; a health observation describes the runtime afterward. See [Core concepts](/docs/concepts) for repositories, environments, workloads, and releases.

## Read the dashboard

Open **Overview** to review recent deployments, active incidents, and workloads needing attention. Follow a workload into its current runtime state or deployment history before retrying an operation. Use [System and workload health](/docs/operate/health) to choose the right observation and [Centralized logs](/docs/operate/centralized-logs) to investigate failures.

## Ownership and access

Towbar runs on your infrastructure. Git stores workload configuration and secret names; the control plane stores encrypted values, SSH trust, and deployment history. Branches allowed to deploy are trusted executable input. Review [Security](/docs/self-hosting/security), protect mapped branches, and keep preview credentials separate from production.
