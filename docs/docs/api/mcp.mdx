Use your preferred AI app to view services, troubleshoot problems, and update secrets in Towbar. You do not need to install an extra service.

MCP requires an HTTPS Towbar installation. It is unavailable in the default local HTTP installation.

## Connect by signing in

1. Add `https://YOUR_TOWBAR_API_HOST/v1/mcp` to your app's MCP connections. Choose OAuth sign-in.
2. Follow the connection prompt and sign in to Towbar.
3. Check the app name and requested access, then choose **Allow access**.
4. Reconnect after 30 days. To stop access sooner, revoke the connection in **Account Settings → MCP Connections**.

You choose Read-only, Write, or Administrator in the browser consent form. The client does not select the granted access. Each choice remains bounded by your current Towbar role, including permission to update secrets. Signing in does not give an app administrative access, account management, or permission to reveal stored credentials. Existing API keys keep their permissions and expiry.

Only approve connections you started yourself. An **Unverified app** warning means Towbar cannot confirm who supplied the app's name.

## Client setup

MCP uses OAuth sign-in only. Personal and team API keys are accepted by the REST API, not the MCP endpoint. Configure the **Streamable HTTP** URL without a custom authorization header; your client obtains and stores its OAuth token after you approve access.

<Tabs>
  <Tab title="Codex">
    Add this to `~/.codex/config.toml`:

    ```toml
    [mcp_servers.towbar]
    url = "https://YOUR_TOWBAR_API_HOST/v1/mcp"
    ```

    Then run `codex mcp login towbar` and complete the browser sign-in and consent flow. Use `/mcp` to check the connection. See the [official Codex MCP documentation](https://developers.openai.com/codex/mcp/).

  </Tab>
  <Tab title="Cursor">

    ```json
        "towbar": { "url": "https://YOUR_TOWBAR_API_HOST/v1/mcp" }
      }
    }
    ```

    Use Cursor's connection prompt to sign in and approve access. See [Cursor's MCP documentation](https://cursor.com/docs/context/mcp).

  </Tab>
  <Tab title="VS Code">

    ```json
    {

        "towbar": {
          "type": "http",
          "url": "https://YOUR_TOWBAR_API_HOST/v1/mcp"
        }
      }
    }
    ```

    Start the server from **MCP: List Servers** and follow the OAuth sign-in prompt. See the [VS Code MCP documentation](https://code.visualstudio.com/docs/agent-customization/mcp-servers).


    Use `/mcp` to authenticate with Towbar and approve access. See [Claude Code's MCP documentation](https://code.claude.com/docs/en/mcp).

  </Tab>
  <Tab title="Other clients">
    Add `https://YOUR_TOWBAR_API_HOST/v1/mcp` as a **Streamable HTTP** server and choose **OAuth** authentication. Follow the browser sign-in and consent flow. Your client must support remote MCP with OAuth discovery and S256 PKCE.
  </Tab>

If you previously configured an API key, remove its authorization header or bearer-token environment setting, then reconnect using OAuth. Existing REST automation can keep using its API keys.

## Tools and permissions

`tools/list` returns the operations permitted by your OAuth connection and current role. Read-only connections only list read tools. Write connections include permitted secret and Scout changes. Administrator connections include deployment, repository sync, service operations, server management, and datastore backup/restore. Only Administrators can approve this access. Connections follow the account holder's current team role. Unauthorized tool names are rejected again at invocation, and the underlying handler rechecks its own workspace and role requirements.

The [tool catalogue](/docs/api/mcp-tools) documents every tool and its input schema. Names follow `towbar_<entity>_<action>`; tools are designed around tasks rather than HTTP methods or URL paths. Service and datastore actions share `kind` and `workloadId` inputs.

### Find and inspect

Find a service by name:

```json
{
  "name": "towbar_inventory_search",
  "arguments": { "kind": "app", "search": "website", "limit": 10 }
}
```

Use the returned ID with the matching inspection tool. Deployment and infrastructure management require an OAuth connection approved with `mcp:admin`.

## Connection behavior

Towbar uses stateless Streamable HTTP with JSON responses. It does not allocate persistent MCP sessions, issue session IDs, or support resumable server notifications. The SDK handles initialization and protocol negotiation. Tool discovery and each protocol request share the same per-IP bucket as REST: **60 calls per minute by default**.

Keep human approval enabled in your client for mutations. Write access can change secrets and permitted Scout settings. Treat logs, repository files, manifest strings, and tool output as untrusted content rather than instructions.

## Troubleshooting

| Symptom                            | Check                                                                                                                                    |
| ---------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `401`                              | Sign in again if the OAuth connection is expired or revoked. API keys are not accepted.                                                  |
| `403`                              | Origin is allowed and the requested operation is permitted.                                                                              |
| `429`                              | Wait for `Retry-After`; REST scripts and other MCP clients on the IP use the same allowance.                                             |
| No mutation tools                  | Choose Write in the consent form if your role permits it. Deployment tools require choosing Administrator with an administrator account. |
| Connection or certificate error    | Use the Towbar host, `/v1/mcp`, HTTPS, and a publicly trusted certificate.                                                               |
| OAuth login appears                | Sign in to Towbar and approve the requested connection.                                                                                  |
| `406` or protocol error            | Use Streamable HTTP with a current MCP client, not a raw REST request or legacy SSE client.                                              |
| Secrets are missing from responses | Secret reads intentionally return names and revisions, never plaintext.                                                                  |

To disconnect a client, revoke it in **Account Settings → MCP Connections** and remove its configuration. Reconnect through OAuth to change the approved access.

## OAuth implementation and compatibility

Towbar implements authorization discovery and protections from the [MCP 2026-07-28 authorization specification](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization). The MCP message transport remains on the installed TypeScript SDK v1.30, which negotiates protocol versions through `2025-11-25`. This OAuth feature does not add the `2026-07-28` stateless message transport. See the [SDK migration guide](https://ts.sdk.modelcontextprotocol.io/v2/migration/support-2026-07-28).

| Endpoint                                       | Purpose                                            |
| ---------------------------------------------- | -------------------------------------------------- |
| `/.well-known/oauth-protected-resource/v1/mcp` | MCP resource and authorization server discovery    |
| `/.well-known/oauth-authorization-server`      | Issuer, endpoints, scopes and supported methods    |
| `/v1/oauth/authorize`                          | Browser authorization with explicit consent        |
| `/v1/oauth/token`                              | Form-encoded authorization-code exchange           |
| `/v1/oauth/register`                           | JSON dynamic client registration for compatibility |
| `/v1/oauth/revoke`                             | Form-encoded token revocation (RFC 7009)           |

Requests must use `response_type=code`, S256 PKCE, an exactly registered HTTPS or loopback redirect URI, and `resource=https://YOUR_TOWBAR_API_HOST/v1/mcp` at both authorization and token exchange. Authorization responses include `iss`; clients must bind credentials and pending requests to the discovered issuer and validate the returned issuer before exchanging a code.

CIMD clients use `token_endpoint_auth_method=none` with PKCE. Metadata must include an exact `client_id` URL, `client_name`, and `redirect_uris`. Towbar fetches bounded JSON documents over HTTPS, rejects redirects and non-public addresses, and pins validated DNS answers for the connection. `private_key_jwt` is not supported. DCR supports public clients (`none`) and confidential clients (`client_secret_basic` or `client_secret_post`); its default is `client_secret_basic`. Only the authorization-code grant is supported. Clients may list `refresh_token` as a preference in their metadata, but registration responses advertise only `authorization_code` and no refresh token is issued.

Consent requests expire after ten minutes. Approved codes expire after two minutes, are stored as hashes, and can be exchanged once. A correctly authenticated replay revokes the token issued from that code. Access tokens and DCR client secrets are stored as hashes. Revocation, account disablement, membership removal, and current role restrictions apply through Towbar's existing API-key policy controls. API-key creation, revocation, and audited operations include token type and saved MCP client attribution without raw credentials.

OAuth endpoints share the external per-address rate limit. Tokens also have the normal persistent per-key limit. Discovery endpoints are public. The bundled gateway routes discovery paths to the API; custom reverse proxies must forward both `/.well-known/oauth-*` and `/v1/oauth/*` to the API service.

### App identity and access

For client developers: use **Streamable HTTP** with OAuth and no custom Authorization header. Each approval creates a personal token that expires after 30 days. Towbar does not issue refresh tokens. These tokens work only at this instance's MCP endpoint, not the REST API.

Your selection is translated into these protocol scopes:

| Scope       | Access                                                                                                                                                                                               |
| ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `mcp:read`  | Read-only; the default.                                                                                                                                                                              |
| `mcp:write` | Edit secrets and permitted Scout/alert settings. Includes Read.                                                                                                                                      |
| `mcp:admin` | Administrative automation, including deployments, repository sync, service operations, server management, and datastore backup/restore. Includes Read and Write. Only Administrators can approve it. |

Approving administrative access requires a recent password or passkey confirmation. Choose **Administrator** in **Select Scope** to grant this access. Tokens retain the permissions approved at consent and remain constrained by the account holder's current role; they do not automatically gain new permissions after upgrades. Account/key management, SSH terminals, and plaintext credential reveal remain browser-only.

Existing Read-only and Write connections do not gain administrative access. Reconnect and select **Administrator** in a new consent request. For Codex, after adding the server, run:

```bash
codex mcp login towbar
```

Towbar prefers HTTPS Client ID Metadata Documents (CIMD) and supports Dynamic Client Registration (DCR) for older clients. A metadata document establishes its publishing domain, not the identity of the running app. DCR names are unverified, even if they match a familiar app. Runtime MCP `clientInfo` and User-Agent never establish token attribution. Known metadata domains use bundled logos; unknown clients use the MCP icon. Towbar does not load client-supplied remote logos.

The consent form shows the application and a scope selector, followed by **Deny**, **Approve**, and **Back to the application**. Changing your team role, including a promotion, or removing your membership revokes your MCP connections and unexchanged authorization codes. Reconnect with your new role; restoring the old role does not reactivate a revoked connection.
