Scout analytics shows how much traffic reaches a public service and which pages receive it. Start with request counts. Add a small script to your website when you also want pageviews. Collection is off until you enable it.

The selected measure, time range, filters, chart metric, and comparison toggle are kept in the page URL. Reload, bookmark, or share the link to reopen the same view. Switching services or environments keeps compatible Analytics selections.

## Turn on request analytics

Install or update Scout Agent from the server’s Scout settings. Add this to your service file, then deploy the service:

```yaml
analytics:
  enabled: true
```

Open **Services → your service → Analytics** and select **HTTP analytics**. Visit the service; data usually appears within a minute. You can see request counts, errors, response times, and the most requested paths.

Requests include API calls, images, scripts, and bots, so request counts do not tell you how many people visited. Analytics is available for single-container services with a public primary domain.

## Count website pageviews

To count pages viewed in a browser, add `pageviews: true` and deploy:

```yaml
analytics:
  enabled: true
  pageviews: true
```

Put this script once in your site’s shared page template:

```html
<script defer src="/.well-known/towbar-analytics/script.js"></script>
```

Select **Web analytics** in Analytics. The script counts the first page and navigation within your site, including single-page applications. It is served from your own service domain. It also measures time spent while a page is visible and clicks to other websites. It does not measure conversions or scroll depth. Blocked scripts and disabled JavaScript reduce the count.

## Optional visitor and session estimates

Pageviews work without identifying visitors. Turn on visitor estimates only if you need to distinguish repeat pageviews from separate browser visits and the setting fits your site’s privacy and consent choices:

```yaml
analytics:
  enabled: true
  pageviews: true
  visitorIdentity: true
```

This adds random IDs in the browser’s local storage. Counts represent browser identities, not people: shared browsers, blocked storage, and deleted IDs affect the estimate. IDs are never derived from an IP address or a browser fingerprint. Leave `visitorIdentity` out to keep visitor and session estimates off.

## Understand visits and exits

With the same pageview script, Analytics also shows:

- **Time spent:** average time a page was visible in a browser tab. Switching tabs or apps stops the timer. This is an estimate of viewing time, not a measure of attention.
- **Bounce rate:** the percentage of finished visits that viewed only one page. A visit finishes after 30 minutes without reported activity. This requires `visitorIdentity: true`.
- **Exit pages:** the last page viewed in a finished visit. This also requires visitor estimates. Towbar cannot tell whether someone closed a tab, typed a new address, or opened another app.
- **Outbound websites:** websites whose links visitors clicked. Only the destination hostname is stored. This includes links opened in a new tab; a click does not prove that the destination loaded or that the visitor left your site.

Update Scout before enabling these measurements. Older records cannot supply missing viewing time or page-order information. Unavailable measurements appear as a dash.

Bounce rate counts all pages in each matching visit, even when a path filter matches only one page. Visits that began before the selected range are excluded from bounce and exit calculations.

## Filter analytics

Choose **Filters**, add conditions, and select **Apply**. All conditions must match. Filters affect totals, charts, breakdowns, and the previous-period comparison.

| Measure       | Filters                                              |
| ------------- | ---------------------------------------------------- |
| Both          | Path and referring website                           |
| HTTP requests | Status, method, and response-time range              |
| Pageviews     | Country, city, browser, device, and outbound website |

Path filters support an exact match or prefix. `/docs/` matches child paths; `/docs` also matches `/docs-old`. Matches are case-sensitive. Omit query strings and fragments. Switching measures retains shared filters and clears filters specific to the old measure.

Response-time filters select histogram ranges. If a stored aggregate spans selected and unselected ranges, Towbar cannot split its duration or bytes exactly; filtered averages and byte totals are unavailable instead of estimated.

An outbound filter selects pages with a click to the chosen hostname during the period. It works without persistent visitor identity. Older pageviews without a temporary page ID cannot be associated with a click.

Enable **Compare** to add the previous period of equal length. A comparison is unavailable when it falls outside retention or has no matching activity. Visitor/session estimates count identities per bucket; adding buckets can count a returning browser more than once.

## Technical details

### Settings and troubleshooting

Retention defaults to 30 days and accepts `7`, `30`, or `90`. `pageviews` and `visitorIdentity` default to `false`. Use `excludePaths` to leave sensitive routes out of both request and pageview collection:

```yaml
analytics:
  enabled: true
  pageviews: true
  retentionDays: 7
  excludePaths:
    - /account
    - /checkout
    - /api/health
```

Exclusions match path prefixes. Set them before collection starts: paths can contain personal information even when query strings are removed.

Compose workloads, datastores, preview deployments, and redirect hostnames are not included. Requests served entirely by a CDN cache never reach the service and do not appear in request analytics.

Scout needs free loopback ports 9468 (UDP) and 9469 (TCP). If they are unavailable, analytics is disabled and performance reporting continues. Scout sends batches about every 30 seconds; allow up to a minute for initial configuration and collection. A warning in Analytics means Scout needs attention on the service’s server.

### Browser behavior and identity storage

The script counts the first page and pathname changes, including browser Back/Forward. Query-string or fragment changes alone do not create a pageview. Viewing time stops when the page is hidden; failed final uploads can lose the last interval.

Allow your own origin in Content Security Policy `script-src` and `connect-src`. The script honors Do Not Track and Global Privacy Control. Privacy signals, blocked scripts, and network failures reduce counts. The public endpoint cannot prove that every event came from a human.

With visitor identity enabled, random visitor IDs expire after 30 days and sessions after 30 minutes without visible-page activity. Scout hashes IDs with the service ID before upload. Disabling identity stops new identity collection; existing history follows retention.

### What each source measures

| Dimension                        | Caddy request analytics                                                | Browser pageviews                                         |
| -------------------------------- | ---------------------------------------------------------------------- | --------------------------------------------------------- |
| Counts and trends                | Requests, including assets, API calls, and bots                        | Reported pageviews and SPA pathname changes               |
| Path                             | Request pathname                                                       | Page pathname                                             |
| Referrer                         | Referrer hostname when sent by the client                              | Referrer hostname when available                          |
| Response                         | HTTP status, method, response bytes                                    | Not measured                                              |
| Latency                          | Total Caddy request duration, mean, histogram, approximate percentiles | Not measured                                              |
| Country and city                 | Not collected                                                          | Local lookup of the verified client IP                    |
| Browser and device               | Not collected                                                          | Coarse user-agent family; bot classification is heuristic |
| Viewing time and outbound clicks | Not collected                                                          | Visible-page duration and destination hostname            |
| Bounce rate and exit pages       | Not collected                                                          | Finished visits using optional session IDs                |
| Visitors and sessions            | Not collected                                                          | Optional random browser IDs                               |

Referrer paths, queries, and credentials are discarded. Missing referrers are **Unknown**, not proof of a direct visit. Percentiles use the upper bound of the containing latency bucket: 10, 50, 100, 200, 500 ms, 1 and 2.5 seconds, followed by an unbounded bucket over 2.5 seconds. The first bucket is strictly below 10 ms; later bounded buckets include their upper limit. Caddy duration includes proxy handling and response transfer; it is not application CPU time or browser page-load time.

Browser pageviews use a local IP lookup for approximate location. Request analytics omits location to keep raw addresses out of Caddy logs. Referrers and outbound destinations retain only hostnames, never their paths or credentials.

Scout trusts Cloudflare client-IP headers only for verified Cloudflare connections or the service's Towbar-managed Tunnel. Other CDNs can appear as the connection's location. Missing, private, or unverified addresses are **Unknown**. Location is not an identity or security signal, and old records cannot be enriched because their IP addresses were not retained.

### Local geolocation database

Scout downloads [DB-IP City Lite](https://db-ip.com/db/download/ip-to-city-lite) over HTTPS and stores it under `/var/lib/towbar-monitoring/geo/`. Visitor IPs are used locally and never sent to DB-IP or the Towbar control plane. IP Geolocation is provided by [DB-IP](https://db-ip.com), under [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/).

Towbar checks for the monthly database edition every day. A failed download keeps the last valid database and retries later. Without a valid file, location is Unknown while other analytics continues.

### Privacy, reliability, and retention

Caddy discards raw headers, query strings, fragments, and IP addresses from analytics logs. Scout uploads sanitized path and traffic aggregates. Browser IPs are used transiently for local location lookup. Raw user agents are reduced to browser/device categories. Optional identity hashes and aggregates are stored in Towbar's PostgreSQL database.

Collection is best effort. Scout accepts up to 1,000 records per second and 512 dimension combinations per pending batch across a server. High-cardinality paths or visitor IDs can cause undercounting. The retry buffer holds at most 10 MiB or one hour; outages beyond that cannot be reconstructed.

Reports require `scout.read`. Retention defaults to 30 days and supports 7, 30, or 90 days. Reducing it hides older records immediately and deletes them during maintenance. Increasing retention does not recover deleted history. Removing analytics from Git stops acceptance after sync; redeploy to remove the Caddy collection routes.

### API

Use the [analytics endpoint](/api-reference/get_apps_by_id_analytics) with API-key authentication. All paths are relative to `/v1/api`:

```bash
curl "https://YOUR_TOWBAR_API_HOST/v1/api/apps/$APP_ID/analytics?kind=pageview&days=7" \
  -H "Authorization: Bearer $TOWBAR_API_KEY"
```

Set `kind=request` for HTTP data or `kind=pageview` for browser data. `days` accepts 15 minutes through 90 days and is limited by the service's retention. Reports include the current and previous periods, ranked dimensions, and applicable metrics.

The optional `filters` parameter is a URL-encoded JSON array of up to eight conditions:

```json
[{ "field": "path", "operator": "startsWith", "value": "/docs/" }]
```

Use the [filter-options endpoint](/api-reference/get_apps_by_id_analytics_filter_options) for selectable values. The reference defines accepted operators, bounds, and response fields.
