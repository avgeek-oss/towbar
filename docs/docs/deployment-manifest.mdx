---
title: "Deployment manifest"
description: "Define environments in towbar.yml and keep each Service or Datastore in its own file."
---

Towbar reads `towbar.yml` at the repository root and discovers workload files under `.towbar/services` and `.towbar/datastores`. A successful sync validates the files together and updates the desired configuration for the mapped environment. It does not deploy the workloads by itself.

## Root configuration

Declare the environment names in `towbar.yml`. Map each name to a branch in **Repository → Environments**. Preview eligibility belongs to an environment and is opt-in:

```yaml title="towbar.yml"
version: 2
environments:
  production: {}
  staging:
    previews:
      enabled: true
```

See [Repositories](/docs/repositories), [environment branches](/docs/repositories/environments), and [sync](/docs/repositories/sync) for the connection and validation flow. The [root JSON Schema](https://github.com/avgeek-oss/towbar/releases/latest/download/repository.v2.json) lists the accepted fields.

## Services

A Service builds source or pulls a prebuilt image. Each has a stable `id` and a `.service.yml` file:

```yaml title=".towbar/services/web.service.yml"
id: web
name: Web
deployment:
  type: dockerfile
  context: .
  dockerfile: Dockerfile
container:
  port: 3000
health:
  path: /health
environments:
  production:
    server: 192.0.2.10
```

Read the [Service manifest](/docs/services/manifest) for every field, [deployment modes](/docs/platform-deployments) for build choices, and [Compose](/docs/services/modes/compose) for multi-container projects. The [Service JSON Schema](https://github.com/avgeek-oss/towbar/releases/latest/download/app.v2.json) defines the exact shape.

## Datastores

A Datastore uses one of Towbar's supported database or cache engines. Put each one in `.towbar/datastores`:

```yaml title=".towbar/datastores/cache.datastore.yml"
id: cache
name: Cache
type: redis
secrets:
  runtime:
    - REDIS_PASSWORD
environments:
  production:
    server: 192.0.2.10
```

Read the [Datastore manifest](/docs/datastores/manifest), then choose an [engine guide](/docs/databases) for required secrets, storage, health checks, and recovery. The [Datastore JSON Schema](https://github.com/avgeek-oss/towbar/releases/latest/download/resource.v2.json) defines the exact shape. Use a [Service with an OCI image](/docs/services/modes/image) for images that are not supported datastore engines.

## Secrets and environment overrides

Commit key names and configuration, but keep secret values outside Git. You can [save values in Towbar](/docs/secrets/towbar) or [import runtime values from Infisical or Doppler](/docs/secrets/external). A missing required value blocks deployment rather than repository sync.

Common settings sit at the top level of each workload file. An entry under `environments` may override supported fields for that environment. Objects merge recursively; arrays replace the common array. Keep an entity's `id` stable when moving or renaming its file so Towbar can retain its history.

## Workload removal

Removing a Service or Datastore file from a valid repository snapshot archives that workload after sync and queues cleanup on every associated server. Cleanup deletes exclusively owned persistent volumes and data, containers, configuration files, and routes. Failed syncs preserve the previous inventory. Back up required data before removal and inspect the server's cleanup history afterward. See [Sync and automation](/docs/repositories/sync) for re-adding workloads, domain handoffs, and cleanup timing.
