A Repository connects a GitHub repository or GitLab project to Towbar. Its `towbar.yml` declares environments, and files under `.towbar/services` and `.towbar/datastores` define workloads. Each connected environment follows a branch selected in Towbar.

Start with [connecting a repository](/docs/repositories/connect), then learn how to [map environment branches](/docs/repositories/environments), [review syncs and automation](/docs/repositories/sync), [handle conflicts and retirements](/docs/repositories/conflicts-and-retirements), and [remove a repository](/docs/repositories/delete). The [manifest guide](/docs/deployment-manifest) explains the Git files shared by services and datastores.

## Connect and sync

1. Configure [GitHub](/docs/integrations/github) or [GitLab](/docs/integrations/gitlab) and grant repository access.
2. Register the target [servers](/docs/servers) and commit a valid [manifest](/docs/deployment-manifest).
3. Choose **Repositories → Add repository**, select environments, and map their branches.
4. Inspect the initial sync. A successful sync imports configuration; deployment is a separate action.

Invalid manifests and unregistered server references fail the sync without partially changing inventory. See [Connect a repository](/docs/repositories/connect) for an example.

**Last synced** is the most recent successfully completed sync across the repository’s environments. Editing connection settings, queued attempts, and failed attempts do not advance it. **Never** means no successful sync has completed.

## Map environments to branches

Use **Environments → Edit branch** to change the branch for an environment. Branch names belong in Towbar, not `towbar.yml`. Saving syncs that branch without deploying or copying another environment's secrets. An invalid sync preserves the last accepted inventory.

See [Environment branches](/docs/repositories/environments) for overrides and preview targets.

## Change configuration

Edit the entity files in Git and merge into the affected environment's mapped branch. A push webhook starts reconciliation; **Sync now** lets you request it explicitly. Review the sync's commit and issues before expecting a deployment.

Rename the display `name` freely, but preserve each workload's `id`. Removing a manifest marks the workload for retirement and preserves runtime and data. Restoring a compatible declaration with the same ID and environment, including in another repository, reuses its identity and history. Resolve duplicate declarations in Git through the Conflicts page.

## Control automatic deployment

Automatic deployment is opt-in. Use the manifest to select which workloads deploy and, for Services, which files count as inputs. The Repository's automatic-deployment controls let you pause automation while investigating an incident or coordinating a maintenance window.

Manual deployment is still a separate action. See [Deployments and releases](/docs/deployments) for the distinction between sync, queueing, execution, and promotion.

## Repository settings

Use **Settings → Notifications** to choose destinations and event categories. Reusable values belong in **Team Settings → Security → Workspace Secrets** (`globals.`) or **Repository Settings → Repository Secrets** (`repo.`). Workload values belong to each Service or Datastore. SSH keys belong to servers; the Cloudflare provider token belongs in the control-plane runtime configuration.

If a repository is missing or a webhook stops arriving, review the relevant [GitHub](/docs/integrations/github#maintain-the-connection) or [GitLab](/docs/integrations/gitlab) integration and its repository access.

## Remove a repository

[Review and remove the repository connection](/docs/repositories/delete) to withdraw its declarations. Compatible workloads transfer to their remaining repository; others enter Retirements or remain in Conflicts. Runtime, secrets, storage and history are preserved. Active operations must finish first. Reconnecting restores the same connection and secrets.
