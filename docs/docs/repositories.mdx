A Repository connects a GitHub repository or GitLab project to Towbar. Its `towbar.yml` declares environments, and files under `.towbar/services` and `.towbar/datastores` define workloads. Each connected environment follows a branch selected in Towbar.

Start with [connecting a repository](/docs/repositories/connect), then learn how to [map environment branches](/docs/repositories/environments), [review syncs and automation](/docs/repositories/sync), [handle conflicts and retirements](/docs/repositories/conflicts-and-retirements), and [delete a repository](/docs/repositories/delete). The [manifest guide](/docs/deployment-manifest) explains the Git files shared by services and datastores.

## Add a Repository

1. Configure the [GitHub](/docs/integrations/github) or [GitLab](/docs/integrations/gitlab) integration and grant it access to the repository or project.
2. Register each target IP address under [Servers](/docs/servers).
3. Commit a valid [manifest](/docs/deployment-manifest) to the repository.
4. Open **Repositories → Add repository**, select the repository, then choose or add environments and map their deployment branches.
5. Open the sync result and confirm it succeeded. The imported services and datastores should now appear under the Repository.

Manifest validation is atomic. Invalid configuration or a reference to an unregistered server fails the sync without partially changing inventory.

Search the branch picker by name when mapping an environment. It includes available branches beyond the first page of results.

Towbar suggests environments from the repository default branch when its configuration is available. You can add other environment names directly, even when the default branch has no manifest. Each selected environment is validated against `towbar.yml` on its mapped branch. Environment names must be unique within a Repository; there is no fixed environment-count limit. Server capacity and repository size still constrain what can run.

## Map environments to branches

Open **Environments** inside the Repository to see its branch mappings and sync
status. **Edit branch** changes a mapping in Towbar; branch names do not belong
in `towbar.yml`. Saving validates and syncs the selected branch without deploying.
If that branch cannot be read or its configuration is invalid, Towbar preserves
the last valid configuration and existing secret values.

PR previews follow the branch mapped to an environment with previews enabled.
For example, staging mapped to `develop` accepts eligible PRs targeting `develop`.

## Change configuration

Edit the entity files in Git and merge into the affected environment's mapped branch. A push webhook starts reconciliation; **Sync now** lets you request it explicitly. Review the sync's commit and issues before expecting a deployment.

Rename the display `name` freely, but preserve each workload's `id`. Removing a manifest marks the workload for retirement and preserves runtime and data. Restoring a compatible declaration with the same ID and environment, including in another repository, reuses its identity and history. Resolve duplicate declarations in Git through the Conflicts page.

## Control automatic deployment

Automatic deployment is opt-in. Use the manifest to select which workloads deploy and, for Services, which files count as inputs. The Repository's automatic-deployment controls let you pause automation while investigating an incident or coordinating a maintenance window.

Manual deployment is still a separate action. See [Deployments and releases](/docs/deployments) for the distinction between sync, queueing, execution, and promotion.

## Repository settings

Use **Settings → Notifications** to choose destinations and event categories. Reusable secret values belong under **Manage → Shared secrets**, while workload values belong to each Service or Datastore. SSH keys belong to servers; the Cloudflare provider token belongs in the control-plane runtime configuration.

If a repository is missing or a webhook stops arriving, review the relevant [GitHub](/docs/integrations/github#maintain-the-connection) or [GitLab](/docs/integrations/gitlab) integration and its repository access.

## Delete a repository

Deleting a repository removes its imported services, datastores, and operational history from Towbar. Running services and Docker data remain on their servers. After deletion, run **Check server** on each affected server and open **Settings → Docker cleanup** to review leftovers and remove them on demand. Volume deletion is a separate, permanent action. See [server cleanup](/docs/servers#clean-up-leftover-workloads).
