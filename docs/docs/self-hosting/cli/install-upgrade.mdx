## `towbar install`

Install the release bundled with the CLI. Run as root on Ubuntu or Debian. The command accepts no arguments and stops if `/opt/towbar/current` already exists.

```bash
curl -fsSL https://github.com/avgeek-oss/towbar/releases/latest/download/install.sh | sudo bash
```

If the CLI is already installed:

```bash
sudo towbar install
```

Choose `http://localhost:4021` for loopback dashboard access (API at `http://localhost:4020`) or separate public HTTPS origins for dashboard and API. Public access requires an A record for each hostname pointing to the host and inbound ports 80 and 443. The installer suggests an API hostname and lets you change it. Custom ports, paths, fragments, HTTPS localhost and non-HTTPS remote URLs are rejected.

The installer verifies and downloads the versioned CLI. The CLI checks release metadata and artifact checksums, prepares Docker, generates `/etc/towbar/config.yml`, pulls images, applies schemas and verifies services. Public installations also obtain a Let's Encrypt certificate and test gateway recovery.

If public setup fails, Towbar stops the incomplete stack and releases ports 80 and 443. It preserves secrets, releases, database data and ACME state for retry. It never enables a public HTTP fallback.

See [Install Towbar](/docs/self-hosting/installation) for account setup and verification.

## `towbar upgrade`

```bash
sudo towbar upgrade          # Latest validated stable release
sudo towbar upgrade v2.0.52   # Selected stable release
```

`update` is an alias for `upgrade`. Versions use `vMAJOR.MINOR.PATCH` and must match the CLI's supported major version.

The CLI reads published stable releases and validated release metadata from GitHub Releases, verifies source and image-manifest checksums, validates configuration, pulls images by digest, applies migrations and checks service health and the running commit. Back up the database and configuration before upgrading; service rollback cannot reverse database migrations.

On success, Towbar keeps the current and previous release directories and application images. It removes older unreferenced Towbar releases without pruning data volumes or unrelated workloads.

Older `/etc/towbar/towbar.yml` configuration is renamed to `config.yml` with contents and permissions preserved. If both exist, resolve the conflict before retrying. If an older CLI starts the upgrade, run `sudo towbar restart` afterward to complete the rename.

Compatible standard installations enable System Health upgrades automatically. Custom installations use the manual CLI path. Use `upgrade`, rather than `install`, for an existing installation.

## `towbar upgrade-service`

Enable System Health upgrades if an older CLI left them disabled:

```bash
sudo towbar upgrade-service enable
```

This requires the standard upstream Linux/systemd installation and a release supporting the host admission protocol. Setup restarts the API with a private runner socket. Once enabled, CLI upgrades also use the runner's readiness checks and job record.

After a failed or interrupted attempt, inspect host logs, the database and service health before acknowledging recovery:

```bash
sudo towbar doctor
sudo towbar upgrade-service resume --acknowledge-recovery
```

Recovery refuses active jobs or unresolved work. See [Upgrades and recovery](/docs/self-hosting/upgrades) for backups, migration limits, admission checks and stale leases.
