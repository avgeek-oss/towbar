## Navigate monitoring

| View                                    | Use it for                                                                                  |
| --------------------------------------- | ------------------------------------------------------------------------------------------- |
| Workspace **Monitor → Logs**            | [Retained application output](/docs/operate/centralized-logs) across workloads and previews |
| Workspace **Monitor → Incidents**       | Active or resolved [alert conditions](/docs/operate/incidents)                              |
| Workspace **Monitor → Vulnerabilities** | [Service image findings](/docs/vulnerability-scanning)                                      |
| Entity **Monitor → Performance**        | [CPU, memory, disk, and network history](/docs/operate/performance) from Scout              |
| Workload **Monitor → Runtime Logs**     | Current container output on demand, without ClickHouse                                      |
| **Settings → System health**            | Towbar control-plane checks, updates, and storage usage                                     |

## Performance history

Select a time range, environment, and container where available. Drag across a chart to zoom. URLs retain the performance filters. Deployment, restart, and hardware markers help correlate changes; missing measurements are gaps.

[Scout Agent](/docs/scout) supplies measurements. [Deployment comparisons](/docs/deployment-comparisons) compares two releases over equal observation windows.

## Alerts, incidents, and vulnerabilities

Configure [Scout Alerts](/docs/scout-alerts) on the relevant entity. Workspace Incidents shows active and resolved conditions; filter by severity. Vulnerabilities shows image scan findings separately.

## System health

Open **Settings → System health → Run checks** for fresh control-plane results. Read the observation time as well as the status. See [Health checks](/docs/operate/health) for diagnostics and [Upgrades](/docs/self-hosting/upgrades) for host CLI upgrades.

### Data and log storage

| Chart        | Includes                                                              | Excludes                                                              |
| ------------ | --------------------------------------------------------------------- | --------------------------------------------------------------------- |
| Data Storage | Towbar, Scout monitoring, and Analytics PostgreSQL tables and indexes | PostgreSQL system overhead, Temporal, backups, and workload databases |
| Log Storage  | Active on-disk parts of the configured ClickHouse `log_records` table | Other tables, inactive parts, other replicas, and backups             |

- Readings are saved every **two hours** and retained for **90 days**. **Run checks** does not take a storage reading.
- Log Storage needs `SELECT` access to `system.parts`. [Set up ClickHouse](/docs/operate/log-collection#connect-external-clickhouse) for the grants.
- Failed or unavailable readings appear as gaps. PostgreSQL sampling continues if ClickHouse fails.
- Older samples without a separate Analytics or Logs reading remain unknown, not zero. Older Analytics usage was included in Monitoring.

## Server and workload health

A successful deployment can become unhealthy later. Read the current runtime state and observation time, then inspect [health checks](/docs/operate/health) and logs.

## CPU and memory caps

Workload charts compare usage with declared limits. On **Servers → All servers**, CPU and memory columns show host capacity. A **% used** line appears when Scout has a measurement; hover or focus to see its age. Missing readings show **Not measured**.

CPU and memory bars turn yellow at **70%** and red at **90%**. A fire indicator beside a Service or Datastore marks usage at or above 90% of its cap; hover or focus to see the higher CPU or memory percentage.

## Follow an operation

Deployment, preparation, backup, and restore histories show stage progress and final results. Relative timestamps refresh every 30 seconds while the page is visible. Absolute times use your account preferences.

For control-plane failures, start with `sudo towbar doctor`. [Troubleshooting](/docs/troubleshooting) lists the next checks; [notifications](/docs/integrations/notifications) covers event delivery.

## Scout Agent

Install Scout from **Server → Settings → Scout Agent** for performance history. Its status and retention are independent of the OTEL Logs Collector. See [Scout Agent](/docs/scout) for reporting, retention, and upgrades.
