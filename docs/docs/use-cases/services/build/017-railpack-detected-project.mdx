`context: .` means the repository root. The source project, start command, and health endpoint must match the selected build mode.

## Towbar manifest

```yaml title=".towbar/services/railpack-detected-project.service.yml"
id: railpack-detected-project
name: Railpack-detected project
deployment:
  type: railpack
  context: .
  version: 0.36.1
  image: ghcr.io/railwayapp/railpack-frontend@sha256:b9166320856c8bbb88789e89077d5a66a7d4cef8afa2e1e232307fb9a92c094e
container:
  port: 3000
health:
  path: /health
environments:
  production:
    server: 192.0.2.10
```

## Configure

1. Register and prepare the example server or servers, connect the repository, and map `production` to the branch containing these files.
2. Sync the repository, inspect the resolved configuration, deploy manually, and perform the verification below before enabling automation.

## Verify

Inspect the detected build and start command, then check the deployed health endpoint. Use Dockerfile mode if the build needs credentials.

For field constraints, see [Service manifest](/docs/services/manifest).
