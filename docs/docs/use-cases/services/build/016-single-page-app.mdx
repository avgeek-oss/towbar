`context: .` means the repository root. The build command must produce the declared output directory; adapt it to the actual project.

## Towbar manifest

```yaml title=".towbar/services/single-page-app.service.yml"
id: single-page-app
name: Single-page app
deployment:
  type: static
  context: .
  output: dist
  buildCommand:
    - npm
    - run
    - build
  nodeImage: node:26-alpine@sha256:40cd011b55415bc894e45b02fdd5a5dfde056921b7d23a64c74f80497af48797
  runtimeImage: nginxinc/nginx-unprivileged@sha256:27985295bdb22a1ef8f712863210bd5877c0f3006494a593e86b3fe0fa55467e
  spaFallback: true
  headers:
    Cache-Control: public, max-age=300
    X-Content-Type-Options: nosniff
container:
  port: 8080
health:
  path: /
environments:
  production:
    server: 192.0.2.10
```

## Configure

1. Register and prepare the example server or servers, connect the repository, and map `production` to the branch containing these files.
2. Sync the repository, inspect the resolved configuration, deploy manually, and perform the verification below before enabling automation.

## Verify

Open a client-side route directly, then reload it. Both requests should load the application.

For field constraints, see [Service manifest](/docs/services/manifest).
