`context: .` means the repository root. The source project, start command, and health endpoint must match the selected build mode.

## Towbar manifests

<CodeGroup>

```yaml title=".towbar/datastores/service-plus-redis-redis.datastore.yml"
id: service-plus-redis-redis
name: Redis
type: redis
container:
  network: application
  networkAlias: service-plus-redis-redis
  resources:
    cpus: 0.5
    memory: 512m
secrets:
  runtime:
    - REDIS_PASSWORD
environments:
  production:
    server: 192.0.2.10
```

```yaml title=".towbar/services/service-plus-redis.service.yml"
id: service-plus-redis
name: Redis service
deployment:
  type: dockerfile
  context: .
  dockerfile: Dockerfile
container:
  port: 3000
  network: application
health:
  path: /health
environments:
  production:
    server: 192.0.2.10
secrets:
  runtime:
    - REDIS_URL
```

</CodeGroup>

## Configure

1. Register and prepare the example server or servers, connect the repository, and map `production` to the branch containing these files.
2. Save each Datastore credential value under **Datastore → Settings → Secrets**, deploy it first, and verify engine readiness before starting a dependent Service.
3. Save the Service's declared keys in its selected environment, or enable and authorize the selected [external-secret provider](/docs/secrets/external). Do not commit the values.
4. Point each Service connection secret at `service-plus-redis-redis` on the database engine's private port. The server and network must match; credentials are saved separately for each Service.
5. Sync the repository, inspect the resolved configuration, deploy manually, and perform the verification below before enabling automation.

## Verify

Connect from the service using the saved Redis password and perform an application-level read and write.

For field constraints, see [Service manifest](/docs/services/manifest) and [Datastore manifest](/docs/datastores/manifest).
