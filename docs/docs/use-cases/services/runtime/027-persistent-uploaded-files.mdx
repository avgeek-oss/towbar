`context: .` means the repository root. The source project, start command, and health endpoint must match the selected build mode.

## Towbar manifest

```yaml title=".towbar/services/persistent-uploaded-files.service.yml"
id: persistent-uploaded-files
name: Persistent files
deployment:
  type: dockerfile
  context: .
  dockerfile: Dockerfile
container:
  port: 3000
  volumes:
    - name: uploads
      mountPath: /app/uploads
      initialData: image
health:
  path: /health
environments:
  production:
    server: 192.0.2.10
rollout:
  type: recreate
  maintenanceMode: true
  reason: Single-writer uploaded files
```

## Configure

1. Register and prepare the example server or servers, connect the repository, and map `production` to the branch containing these files.
2. Sync the repository, inspect the resolved configuration, deploy manually, and perform the verification below before enabling automation.

## Verify

Write a test file as the application user, redeploy, and confirm the file remains readable.

For field constraints, see [Service manifest](/docs/services/manifest).
