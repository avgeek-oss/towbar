**Related reading:** [Towbar secrets](/docs/secrets/towbar).

`context: .` means the repository root. The source project, start command, and health endpoint must match the selected build mode.

## Towbar manifest

```yaml title=".towbar/services/required-runtime-credential.service.yml"
id: required-runtime-credential
name: Runtime credential
deployment:
  type: dockerfile
  context: .
  dockerfile: Dockerfile
container:
  port: 3000
health:
  path: /health
environments:
  production:
    server: 192.0.2.10
secrets:
  runtime:
    - API_TOKEN
```

## Configure

1. Register and prepare the example server or servers, connect the repository, and map `production` to the branch containing these files.
2. Save the Service's declared keys in its selected environment, or enable and authorize the selected [external-secret provider](/docs/secrets/external). Do not commit the values.
3. Sync the repository, inspect the resolved configuration, deploy manually, and perform the verification below before enabling automation.

## Verify

Save the declared value in the selected environment, deploy, and confirm the application can use it without logging it.

For field constraints, see [Service manifest](/docs/services/manifest).
