`context: .` means the repository root. The source project, start command, and health endpoint must match the selected build mode.

## Towbar manifest

```yaml title=".towbar/services/pre-deploy-migration.service.yml"
id: pre-deploy-migration
name: Pre-deploy migration
deployment:
  type: dockerfile
  context: .
  dockerfile: Dockerfile
container:
  port: 3000
health:
  path: /health
environments:
  production:
    server: 192.0.2.10
hooks:
  preDeploy:
    command:
      - node
      - scripts/migrate.js
    timeoutSeconds: 300
```

## Configure

1. Register and prepare the example server or servers, connect the repository, and map `production` to the branch containing these files.
2. Sync the repository, inspect the resolved configuration, deploy manually, and perform the verification below before enabling automation.

## Verify

Run the migration against test data, verify the schema, and check compatibility with the previous application release.

For field constraints, see [Service manifest](/docs/services/manifest).
