These are separate files in one repository. A shared Docker network works only when the workloads run on the same server; Towbar does not automatically order their deployments or copy secret values between them.

## Towbar manifests

<CodeGroup>

```yaml title="redis"
# .towbar/datastores/api-worker-and-redis-redis.datastore.yml
id: api-worker-and-redis-redis
name: API-worker stack Redis
type: redis
container:
  network: application
  networkAlias: api-worker-and-redis-redis
  resources:
    cpus: 0.5
    memory: 512m
secrets:
  runtime:
    - REDIS_PASSWORD
environments:
  production:
    server: 192.0.2.10
```

```yaml title="api"
# .towbar/services/api-worker-and-redis-api.service.yml
id: api-worker-and-redis-api
name: API-worker stack
deployment:
  type: dockerfile
  context: .
  dockerfile: Dockerfile
container:
  port: 3000
  network: application
health:
  path: /health
environments:
  production:
    server: 192.0.2.10
secrets:
  runtime:
    - CACHE_URL
```

```yaml title="worker"
# .towbar/services/api-worker-and-redis-worker.service.yml
id: api-worker-and-redis-worker
name: Worker
deployment:
  type: dockerfile
  context: .
  dockerfile: Dockerfile
container:
  port: 3000
  network: application
health:
  path: /health
environments:
  production:
    server: 192.0.2.10
secrets:
  runtime:
    - QUEUE_URL
```

</CodeGroup>

## Configure

1. Register and prepare the example server or servers, connect the repository, and map `production` to the branch containing these files.
2. Save each Datastore credential value under **Datastore → Settings → Secrets**, deploy it first, and verify engine readiness before starting a dependent Service.
3. Save the Service's declared keys in its selected environment, or enable and authorize the selected [external-secret provider](/docs/secrets/external). Do not commit the values.
4. Point each Service connection secret at `api-worker-and-redis-redis` on the database engine's private port. The server and network must match; credentials are saved separately for each Service.
5. Sync the repository, inspect the resolved configuration, deploy manually, and perform the verification below before enabling automation.

## Verify

Submit a job through the API, confirm the worker processes it, and test client reconnection.

For field constraints, see [Service manifest](/docs/services/manifest) and [Datastore manifest](/docs/datastores/manifest).
