## Towbar manifest

```yaml title=".towbar/datastores/incident-investigation.datastore.yml"
id: incident-investigation
name: Incident investigation
type: postgres
container:
  network: application
  networkAlias: incident-investigation
  resources:
    cpus: 1
    memory: 1g
secrets:
  runtime:
    - POSTGRES_USER
    - POSTGRES_DB
    - POSTGRES_PASSWORD
environments:
  production:
    server: 192.0.2.10
backup:
  integration: aws
  schedule:
    cron: 0 3 * * *
    timezone: UTC
  retention:
    keepLast: 14
```

## Configure

1. Register and prepare the example server or servers, connect the repository, and map `production` to the branch containing these files.
2. Save each Datastore credential value under **Datastore → Settings → Secrets**, deploy it first, and verify engine readiness before starting a dependent Service.
3. Enable the selected backup integration and configure its runtime storage credentials and destination before creating a recovery point. A manifest policy alone does not provide storage access.
4. Sync the repository, inspect the resolved configuration, deploy manually, and perform the verification below before enabling automation.

## Verify

Inspect freshness separately from object-readiness errors. Follow the failed check before retrying backup or restore.

For field constraints, see [Datastore manifest](/docs/datastores/manifest).
