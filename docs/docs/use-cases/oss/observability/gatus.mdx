Gatus needs a versioned list of endpoints to check. The sample checks one public URL; it does not require a separate database for this first setup.

## Towbar manifest

```yaml title=".towbar/services/gatus.compose.yml"
id: gatus
name: Gatus
file: deploy/gatus/compose.yml
strategy: maintenance
services:
  gatus:
    port: 8080
    domains:
      - gatus.example.com
    ingress:
      type: proxy
environments:
  production:
    server: 192.0.2.10
```

## Compose project

services:

```yaml title="deploy/gatus/config.yaml"
endpoints:
  - name: Example site
    url: https://example.com
    interval: 1m
    conditions:
      - "[STATUS] == 200"
```

</CodeGroup>

## Configure

1. Prepare the example server, connect the repository, and map `production` to the branch containing these files. Replace the example server IP and domain.
2. Commit the Towbar manifest under `.towbar/services/` and the Compose files under `deploy/gatus/`, using the paths shown above.
3. Sync the repository and inspect the resolved Compose project. Save the runtime values below if this example declares any.
4. Replace the example endpoint with a URL you control. Add alerting only after the basic check works; destination credentials belong in Towbar runtime secrets, not this file.
5. Deploy it manually and run the verification below before enabling auto-deploy.

## Verify

Open the status page, verify that the endpoint has a recent successful check, then temporarily use a failing URL to confirm the failure appears.

For field constraints, see [Compose guide](/docs/services/modes/compose).
