---
title: "Sync and automation"
description: "Understand Git reconciliation, manual syncs, and when a sync becomes a deployment."
---

A sync validates an immutable repository commit and updates Towbar's inventory. It is distinct from a deployment. Initial connection, branch changes, and **Sync now** import configuration without starting workloads.

## Review a sync

Open a Repository's **Environments** page and inspect the latest sync for its commit, outcome, and issues. A successful sync can add or update services and datastores, mark missing IDs for retirement, and update notification subscriptions. Invalid configuration fails atomically; the last valid configuration remains active.

Pushes to a mapped branch start reconciliation through the source-control webhook. Use **Sync now** when you need to inspect the current branch state immediately. If no update arrives, check the integration's repository access and webhook delivery before retrying.

Use **Sync All** on the Repositories page to queue a sync for every active repository's connected environments, including repositories hidden by filters. It does not deploy workloads. Failed requests are reported separately; other repositories still sync.

## Remove a workload

Delete its Service or Datastore YAML file and sync the mapped environment. The workload appears in **Retirements**. Its runtime, secrets, storage and history remain; automatic deployments stop.

Restore a compatible manifest with the same ID in the same environment to resume management. It can live in the original repository or another connected repository. Multiple repositories declaring that ID create an informational conflict. Correct Git and sync both repositories to resolve it.

Permanent removal requires an administrator's explicit confirmation on the Retirements page. See [conflicts and retirements](/docs/repositories/conflicts-and-retirements) for repository moves, compatibility checks and removal effects.

## Enable automatic deployment deliberately

Auto-deploy is opt-in on each workload. For a Service, limit triggering changes to files that can affect its build:

```yaml title=".towbar/services/web.service.yml"
id: web
name: Web
autoDeploy:
  inputs:
    - package.json
    - pnpm-lock.yaml
    - apps/web/**
```

The paths are relative to the repository root. Include shared packages and build files, not only the Service directory. The Repository's automation controls can pause automatic work during maintenance; manual deployment remains a separate action. A configuration update can therefore sync successfully without deploying a new release. A missing manifest never authorizes cleanup.

See [Deployments and releases](/docs/deployments) for queueing and promotion, and [environment branches](/docs/repositories/environments) for branch changes.
